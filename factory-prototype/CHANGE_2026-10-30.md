# Mid-order improvement / v0.2
Title-local; no save schema or economy change. Goal: make the approved notice → improve → resume loop possible before a whole order finishes.

Observed v0.1 defects: all active work rejected placement; menus hid toast errors; first unshipped order obscured a ready second order; queue sizes were not visible; accepted orders remained in a paused modal.

Changes: request placement while busy, drain assigned stages without starting new stages, then pause for placement. Preserve partially processed parts and resume prior running speed after placement/cancel. Check workers and unfinished parts remain reachable; no placing equipment atop unfinished material. Cache valid floor cells during the pause. Show counts of waiting/carrying/working parts by next stage; select ready orders first. Accepting an order closes the modal and starts production; explicitly labelled accordingly. Modal errors get an in-dialog status message.

Acceptance: drain is bounded by current assignments, creates no new jobs, loses no parts or paid work, and permits finish/dispatch after rearrangement. Counts conserve parts and do not mutate simulation. Existing schema-1 states still load. New fields are presentation-only and do not require save migration.

Scope: docs/forge-preview, domain regression tests, title-local documentation. Revert this commit for rollback; existing schema remains compatible. No new gameplay systems, production release, native iPhone claim or legacy FLOTRA changes.
