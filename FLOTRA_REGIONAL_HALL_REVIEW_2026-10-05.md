## Save safety

Schema 4 adds hall state. Frozen validators first validate schema 1–3; valid original fields, including in-flight positions, reservations, clocks, pending movement, wallet, history and historical boundary medals are preserved rather than normalized.

The existing namespace and rolling backup remain. The first schema-4 write also preserves the exact validated old text in an immutable pre-v4 archive. Subsequent envelopes carry its SHA-256 binding. Existing archives are never overwritten or deleted. Missing, corrupt, conflicting, unreadable or quota-blocked protection fails closed while readable progress stays available. The archive has no automatic rollback UI and is not silently substituted for a corrupt primary. See `FLOTRA_SCHEMA4_SAVE_SAFETY_2026-10-05.md`.

## Exact-head CI path

The workflow checks out the explicit pull-request head. New regional jobs actually run the new contract/migration/archive journeys, rather than only the previous campaign.

`regional-hall-renderer-control` checks out the public PR152 control by immutable SHA, then runs control288, candidate288, candidate-storage480 and candidate-corridor480 in one browser/runner at the same CSS/DPR/checkpoint regime. It asserts actual PCK hashes against the frozen manifest, verifies production-source hashes and bridge parity, and records browser/GPU environment, thresholds, captures and progress. Every active sample must remain visible, running and unfinished with the expected cargo and hall plan. The CI hall journey separately observes a changed timed save while still running, before any pause action; that strengthened assertion awaits CI. It uses the original percentile convention and unchanged limits. A failed control keeps the job failing with an explicit environment-control result; no automatic approval or threshold adjustment follows.
