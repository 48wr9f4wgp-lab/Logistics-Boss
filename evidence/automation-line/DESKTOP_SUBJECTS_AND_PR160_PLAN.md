## Candidate runtime focus fix and final local qualification

Root cause: `_sync_focus()` assigned a next/previous ring from persistent `CloseSheet` to dynamic `StartTrial`. `_open_sheet()` then detached and freed the dynamic content. The old implementation returned early for closed modals or an empty eligible-button list without clearing surviving paths; save protection disables CloseSheet and leaves no enabled buttons. Real Tab traversal therefore tried to resolve a destroyed StartTrial. No directional-neighbor paths are assigned; the regression audits next, previous and all four directional properties.

The runtime change is limited to `prototype/layout_hud.gd` (19 added / 4 removed lines): track the prior ring, clear it before content removal and every rebuild, include only visible/enabled/FOCUS_ALL buttons, release focus in an empty protected sheet, and return an ineligible owner to the first eligible button. A Button type guard precedes lookup in Array[Button], preserving support for an existing SubViewportContainer focus owner. No input suppression, console exclusion, gameplay, save schema, economy, equipment rendering or layout geometry change.
